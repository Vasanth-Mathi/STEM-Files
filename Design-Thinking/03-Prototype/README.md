# Prototype

## What This Stage Means

A prototype is a **simple, testable representation of an idea**.

It is not the final product.

The purpose of a prototype is to learn quickly, cheaply, and safely before spending too much time or material.

```text
Selected Idea
      |
      v
Build Something Testable
      |
      v
Let People Experience It
      |
      v
Learn What Works / Fails
```

## A Prototype Can Be

- a paper sketch,
- a cardboard layout,
- a screen wireframe,
- a clickable interface,
- a role-play,
- a storyboard,
- a physical model,
- a simplified mechanism,
- a circuit prototype,
- a mock service counter,
- a small working section of a larger system.

## Good Prototype Questions

Before building, ask:

- What assumption are we testing?
- What does the user need to experience?
- What is the simplest version that can test this?
- Which parts do not need to be built yet?
- What can be represented instead of fully constructed?
- What should we measure or observe?

## Low-Fidelity First

An early prototype should normally be:

- quick,
- inexpensive,
- easy to change,
- understandable,
- safe,
- focused on one important question.

A beautifully finished model can actually be less useful if students become unwilling to change it.

## Prototype Record

Students should record:

- purpose of the prototype,
- assumption being tested,
- materials,
- labelled sketch,
- what is included,
- what is intentionally missing,
- how it will be tested,
- photographs or screenshots where permitted,
- changes made between versions.

## Version Thinking

```text
Version 1 ---> Test ---> Change ---> Version 2
```

The change is part of the learning. A first prototype that exposes a problem is useful evidence.

## Check Before Moving Forward

- Can someone interact with or understand the prototype?
- Does it test the important assumption?
- Is it simple enough to change?
- Are safety limits clear?
- Have we recorded what Version 1 is meant to test?
