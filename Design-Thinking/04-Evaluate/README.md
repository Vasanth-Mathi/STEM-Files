# Evaluate

## What This Stage Means

Evaluate means testing the prototype and using **real evidence** to judge how well it meets the user's need.

The question is not:

> Do we like our project?

The better question is:

> What happened when people used or tested it?

```text
Prototype
    |
    v
Test with Criteria / Users
    |
    v
Observe + Measure + Listen
    |
    v
Identify Successes and Problems
```

## What Can Be Evaluated

Depending on the project, students may examine:

- ease of use,
- time taken,
- number of errors,
- comfort,
- accessibility,
- clarity,
- safety,
- reliability,
- task completion,
- user understanding,
- repeated performance.

## Before Testing

Define success criteria first.

Examples:

- user can complete the task without help,
- instructions are understood on the first attempt,
- prototype performs the required action in repeated trials,
- important controls can be reached comfortably,
- user can identify the next step without explanation.

## During Testing

Students should:

- observe without constantly helping,
- record what the user does,
- note where hesitation occurs,
- note unexpected behaviour,
- measure relevant results,
- ask neutral questions,
- record both positive and negative feedback.

## Useful Evaluation Questions

- What was easy?
- What was difficult?
- Where did you hesitate?
- What did you expect to happen?
- What confused you?
- What felt uncomfortable?
- Which part would you change first?
- Would the experience be different for another user?

## Avoid

- testing only once,
- asking leading questions,
- changing the success criteria after seeing the result,
- hiding failures,
- using only team opinions,
- saying "it works" without evidence.

## Check Before Moving Forward

- Did we test against clear criteria?
- Did we collect evidence?
- Did we notice unexpected user behaviour?
- What failed?
- What remains uncertain?
- What should be changed before another version?
