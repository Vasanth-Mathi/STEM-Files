# 100 Designing Problem Statements

> A browsable bank of **100 grounded, human-centred Design Thinking problem statements**.

These entries intentionally describe **problems only**. They do not suggest products, apps, inventions, technologies, or preferred solutions.

Each entry contains:

- `Problem Statement` — the user group, context, difficulty, consequence, and human impact in one complete statement.
- `Possible Core Problems` — several underlying issues that may be contributing to the situation.
- `Empathy Factor` — how the situation can affect the user's feelings, comfort, safety, independence, confidence, time, or participation.

> [!IMPORTANT]
> The listed core problems are **possible causes to investigate**, not confirmed facts. Students should validate them through observation, interviews, evidence, or other appropriate research.

## How Students Should Use This Bank

Choose one statement and investigate it further.

1. Identify the exact user group and place or context.
2. Observe the situation where appropriate.
3. Ask neutral questions.
4. Check which possible core problems are actually supported by evidence.
5. Remove causes that are only assumptions.
6. Rewrite the problem statement after learning more.
7. Move to ideation only after the user's real need is reasonably understood.

> [!NOTE]
> A strong Design Thinking problem statement can change after empathy work. The purpose of this bank is to provide a realistic starting point, not a finished diagnosis.
