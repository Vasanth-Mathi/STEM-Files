# Project-Based Learning and Capstone Framework

## Purpose
Help teachers turn tool practice into purposeful projects with requirements, testing, evidence, and improvement.

## Project Progression

```text
Bootcamp
   |
   v
Guided Mini-Project
   |
   v
Second Application
   |
   v
Capstone Challenge
   |
   v
Testing + Improvement
   |
   v
Presentation / Reflection
```

## Project Brief Template

### Problem / Purpose
What need, question, or task is the project addressing?

### User / Context
Who will use it or where will it operate?

### Requirements
List 3-5 things the solution must do.

### Constraints
Examples:
- time
- available components
- cost
- size
- safety
- school network access
- privacy

### Success Criteria
Use measurable statements.

Examples:
- completes the task correctly in at least 3 of 5 trials
- detects an object within a defined range
- displays the required data clearly
- responds safely when a sensor reading fails

### Evidence Required
- idea / design sketch
- circuit or system diagram
- code or logic record
- test table
- failure log
- Version 1 / Version 2 comparison
- individual explanation

## Teacher Rule
A finished model is not enough evidence of understanding. Students should explain the logic, circuit, data, design decision, or testing behind it.
