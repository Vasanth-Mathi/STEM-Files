# Assessment and Learning Evidence

## Purpose
Provide a simple way to assess STEM learning using evidence rather than judging only whether a final project works.

## Suggested Assessment Areas

| Area | Evidence to Look For |
|---|---|
| Understanding | Student explains concepts, components, logic, or design principles |
| Application | Student uses taught knowledge in a working task |
| Design | Choices are connected to a purpose, user, or requirement |
| Testing | Student records repeated or meaningful tests |
| Troubleshooting | Student identifies a fault and explains how it was investigated |
| Improvement | Version 2 is changed using evidence from testing or feedback |
| Responsible Use | Student follows safety, privacy, attribution, and ethical-use expectations |
| Communication | Student presents clearly and answers questions using evidence |
| Collaboration | Student can explain personal contribution within team work |

## Four-Level Scale

### Emerging
Needs substantial support to complete and explain the task.

### Developing
Completes parts of the task and explains some ideas with support.

### Proficient
Completes the required task, explains key decisions, and provides suitable evidence.

### Advanced
Applies learning independently, tests systematically, justifies improvements, and communicates limitations clearly.

## Evidence Examples
- entry check
- concept questions
- project file
- circuit record
- calibration data
- test results
- screenshot/photo where permitted
- debugging log
- presentation
- individual viva
- reflection

## Minimum Mastery Principle
Mastery should be demonstrated through evidence and explanation, not assumed from attendance or team membership.
